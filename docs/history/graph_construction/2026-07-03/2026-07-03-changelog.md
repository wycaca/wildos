## 诊断结论摘要

- 历史 changelog 中已有的 `文档同步` 小节保留, 不做回写
- 新增或更新 changelog 时只需要记录已完成, 实测结果, 诊断结论摘要和后续待办
- GridMap cell 到 world 的转换不能再依赖手动 `origin_x = center + length / 2` 的无 yaw 特例
- 后续 GridMap 坐标问题应优先跑专项 round-trip 测试, 再看 RViz marker 偏移
- debug projection adapter 和 graph construction 应共用同一套 GridMap layer 解码
- robot anchor 应作为 graph 起点兜底机制, 不能掩盖地图分类或坐标映射错误
- stage timing 已保持分层, builder 只返回纯数据, ROS node 只负责日志策略
- 慢帧诊断现在可以直接区分 grid 分类, builder 内部阶段, ROS message 转换和发布耗时
- 默认启动面现在只保留完整 2D / 3D 链路, 单节点 debug 应使用 `ros2 run`
- `grid_map_to_occupancy` 是 debug adapter, 不是 elevation graph 的默认输入
- 当前默认 profile 是 `isaac`, 2D 默认使用 LiDAR OccupancyGrid baseline, 3D 默认使用 elevation GridMap backend
- `wildos` 缺少 `omegaconf` 的直接原因是 install console script 使用 `/usr/bin/python3`, 而依赖在项目 `.venv` 中
- `wildos` 缺少 `explorfm` 属于同一类 Python 解释器路径问题, 不是模型代码本身不可用
- 只修 shebang 不够稳, 因为重新 build 或直接 `ros2 launch` 可能绕过启动脚本修复, 2D launch 现在支持显式 Python prefix
- Isaac 2D 默认需要 LiDAR fallback static TF, 否则 grid builder 启动早期可能看不到 `lidar -> map` 连通链路
- 2D baseline 不会直接显示完整仿真地图, 它只能显示 LiDAR 射线观测过的局部 OccupancyGrid
- Isaac LiDAR 如果按旋转扇区分批发布点云, 旧实现只用最新一帧会看到扇形慢慢转动, 需要累计最近扫描帧生成局部 grid
- Unity / Zenoh 运行时 graph 和 viz 不发布的直接断点是 `/spot1/odom_for_scoring` 没有消息
- Unity profile 不应默认使用 Isaac 的 TF-only odom 策略, 否则缺少 `map -> base_link` TF 时 odom adapter 会丢弃 `/unity/odom`
- `fallback_to_message` 必须作为 bool 参数传给 rclpy 节点, 字符串 `'true'` 会导致 `odom_frame_adapter` 初始化阶段退出
- `/spot1/nav_graph_viz` 没有 publisher 时, 优先检查 WildOS 进程是否已经退出
- `explorfm` 当前是仓库内源码包, 直接在仓库目录导入成功不代表 ROS 子进程能导入, WildOS 子进程必须显式获得仓库根目录 `PYTHONPATH`
- WildOS 的 `--config-override key=value` 走 OmegaConf dotlist, 包含 `{}` 的字符串值必须加 YAML 引号
- Unity 3D 高程图不显示的直接原因是 elevation mapping 等待 `map -> base_link`, 但 live TF 中机器人 body frame 是 `odom_fram`
- Unity profile 下 3D aligned 点云 frame 必须保留真实传感器 frame `livox_frame`
- Unity profile 下更合理的长期语义是保留点云 frame 为 `livox_frame`, 让 elevation mapping 使用已有 `odom_fram -> livox_frame` TF 做转换, 不要仅修改 header frame
- 高程图没有连续地面不是 RViz 配色问题, 当前 GridMap 大部分 cell 没有 elevation 有效值
