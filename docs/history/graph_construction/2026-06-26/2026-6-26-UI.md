# 论文 WildOS 复现方案：Graph Construction 架构与实现规范

**日期:** 2026-06-26  
**版本:** v2.0 (基于论文视频 UI 逆向修正版)  
**目标:** 明确 Graph Construction 模块在 WildOS 中的 2.5D 几何记忆层定位，规范输入输出接口、核心拓扑算法边界与可视化渲染分层，指导分阶段增量复现。

---

## 一、 系统定位与当前结论

Graph Construction 是 WildOS 的几何记忆层，负责把局部几何感知和可通行性结果增量组织成 NavigationGraph。

### 核心结论
1. 非纯2D/非完全共面: 根据论文实际运行画面，该模块采用 2.5D 分层拓扑（Layered Topology） 架构。所有几何节点、边缘、Frontier 必须顺应 2.5D 地形表面（Elevation Surface）起伏，绝不能强行压平到同一个 2D 平面。
2. Required External Component: 公开仓库中该模块未开源，但它是部署时必须同时运行的外部组件之一，与 Elevation Mapping CuPy、DLIO、Nav2 并列。
3. 最小职责: 本模块不直接做语义决策，而是稳定输出可被评分和规划的稀疏拓扑图，为视觉语义模型（ExploRFM）提供稳定的几何骨架。

## 二、 接口契约与数据结构 (Data Contract)

### 1. ROS 2 通信接口契约

* 订阅源 (Subscriptions):
  - /elevation_mapping_node/elevation_map_raw (grid_map_msgs/msg/GridMap) -> 提供局部高程 elevation 与可通行性 traversability 图层
  - /spot1/odom (nav_msgs/msg/Odometry) -> 机器人实时 3D 里程计位姿
  - /tf, /tf_static -> 维护坐标变换
* 发布源 (Publications):
  - /spot1/nav_graph (graphnav_msgs/msg/NavigationGraph) -> 供视觉模块和 Planner 消费的核心图数据
  - /spot1/graph_construction_viz (visualization_msgs/msg/MarkerArray) -> 供 RViz 显示的分层视觉 Overlay

## 三、 核心拓扑算法与边界规则 (Algorithmic Boundaries)

### 1. Z 轴对齐规则 (Z-Clamping)
* 给定任意节点 P(x, y)，其 z 值必须通过查询 GridMap 的 elevation 图层获得。
* 查询时需实现双线性插值。若该 Cell 的值为 NaN（代表未探测到的区域边缘），则该节点不允许作为 Free Node，只能作为 Frontier 候选，且其 z 值暂取邻近有效地面高度。

### 2. 增量更新与 UUID 跟踪 (数据关联)
* 新旧匹配: 每当新一帧提取出 Frontier 聚类中心 P_new 时，必须在历史拓扑图中进行 KD-Tree 最近邻搜索。
* 距离判定: 设阈值距离为 0.5m。若新旧节点距离小于 0.5m，则判定为同一节点，必须继承并保留旧节点的 UUID；否则生成全新 UUID。
* 消亡与转换: 若某个历史 Frontier 节点在当前帧被划入了可通行区域，将其 is_frontier 标签置为 false，降级转为普通空间记忆节点（Free Node），绝不能物理删除。

### 3. 防御性异常处理 (Guardrails)
* TF 超时防御: 查询 lookupTransform 时必须包裹 try-catch / try-except 块，设置超时等待为 0.1s。若失败，直接复用上一帧的状态。
* 全局 NaN 穿透: 当 GridMap 全是 NaN 时，模块应立刻锁定当前拓扑图，停止增量更新，维持历史空间记忆。

## 四、 可视化 Overlay 分层规范 (Visualization)

为了在 RViz 中避免画面闪烁（Z-fighting），各视觉元素严格遵循以下 z 轴微小偏移分层：
1. 地形表面: 原始高程面 elevation 
2. 机器人投影 (白色 SPHERE): 强制贴地（$(x,y)$ 处地表 elevation）
3. 拓扑节点 (绿色 SPHERE): elevation + 0.01m (略高于地表，避免被半埋)
4. 拓扑边缘 (红色细线 LINE_LIST): 两端点 elevation + 0.02m
5. 彩虹得分环 (TRIANGLE_LIST): Node.pose.z + 0.03m
6. 规划路径 (绿色粗线 LINE_STRIP): 路径点 elevation + 0.05m (悬浮于所有元素最上层)

## 五、 分阶段复现路线

* 阶段 1：消息接口与假图闭环 -> 编写最小化 Python ROS 2 节点，定时发布包含固定节点和 Frontier 的假图，让 visual_navigation 和 planner 能跑通通信。
* 阶段 2：基于静态 Grid 的几何提取 -> 接入静态 2D 网格，编写边界查找和空间聚类算法，自动生成 Node 位置与 frontier_points。
* 阶段 3：时序增量更新与数据关联 -> 引入机器人真实里程计，实现动态 KD-Tree 匹配与 UUID 锁死逻辑，确保节点在时序上不闪烁。
* 阶段 4：接入 2.5D 真实高程图 -> 正式对接高程图消息，利用双线性插值赋予真实的物理 z 值，使红线网格随着山坡平滑铺展。
* 阶段 5：WildOS 全系统联调与闭环 -> 贯通整个决策闭环，验证彩虹得分环动态改变颜色且 Planner 能正确做出避开死胡同的探索决策。
