### 2.3 目标定位

### 5.1 盲区修补范围

### 5.2 启动观察

增加正式探索前的启动观察状态, 建议状态名为 `STARTUP_OBSERVATION`

启动时默认先静止等待, 不默认原地旋转 360 度

原因:

- Mid-360 已经具有 360 度水平视场, 绕竖直轴旋转不会改变固有的垂直视场和脚下近场盲区
- 雷达采用持续扫描, 静止积累数帧点云也能提高周边点云密度
- 启动旋转会延迟第一条路线, 还可能在 DLIO 尚未完全稳定时增加姿态健康告警
- 三相机和局部遮挡可能从小角度扫描中受益, 但这属于条件触发的补救, 不是修补脚下 unknown 的主要手段

预期流程:

```text
DLIO 健康
  -> 高程图和导航图连续有效
  -> WildOS 和 scored graph 已就绪
  -> 静止积累有效地图
  -> 前向区域足够可规划: 直接开始探索
  -> 前向区域不足: 小角度扫描后重新判断
  -> 再进入 SEARCHING_WITH_INITIAL_GOAL
```

默认动作:

- 静止等待 2 至 3 s, 或累计 10 至 15 帧有效高程图, 两个条件取较晚者
- 至少收到 3 帧连续有效 nav graph 和 scored graph
- 检查机器人脚下可达地面、前向 free 区域和前向 Frontier
- 条件满足后直接开始探索, 不为了形式上的全景观察额外旋转

条件扫描:

- 仅在前向区域 unknown 比例过高、没有前向 Frontier 或三相机存在明显未覆盖方向时触发
- 首轮采用相对初始朝向左右各 30 至 45 度的小角度扫描, 最后回到初始探索朝向
- 使用 odom 累计 yaw 判断角度, 不使用固定定时器猜测是否转到位
- 角速度先限制在 15 至 20 度每秒, 不直接使用 360 度连续旋转
- 旋转期间只允许角运动, 不允许平移
- DLIO、地图或控制链路不健康时立即暂停, 恢复后继续或退回静止等待
- 完成扫描并收到若干连续有效 graph 后才允许选择第一条探索路线
- 启动观察期间不累计探索分支的无进展和路径失效计时

完整 360 度扫描只保留为实验开关, 用于验证后方目标快速发现或相机覆盖, 不作为默认启动流程

原地旋转不能消除 Mid-360 固有的脚下垂直视场盲区, 真正的脚下 unknown 仍由高程图 initializer 和 1.2 m 保守修补负责

## 6. 阶段三: 目标证据和粗目标观察

### 6.1 双门槛视觉确认

保留目标首次进入门槛 `0.120`, 不降低首次触发标准

新增独立的确认门槛, 初始建议值为 `0.115`, 可在 0.110 至 0.118 范围内通过无目标场景和真实目标场景对比确定

预期语义:

```text
尚无候选
  -> 峰值 >= 0.120 才进入候选窗口
候选窗口正在确认
  -> 后续证据峰值 >= 0.115 可计入确认
确认完成
  -> 仍保持现有像素 Mask 阈值和最小区域要求
```

以下条件第一轮不调整:

- Mask 像素阈值 `0.100`
- 最小区域像素 `300`
- 2/3 帧确认窗口
- Goal Mux 粗目标置信度 `0.5`
- 粗目标距离、高度和协方差物理门控

不能同时降低视觉门槛和融合置信度, 否则无法判断误检或错误深度来自哪一层

### 6.2 粗目标观察状态

当前 Planner 到达视觉粗目标半径后会直接发布单点停止路径, 即使融合仍处于 `TRACKING`

当前 `goal_radius` 统一为 3.0 m, 目标融合消息的 orientation 又是单位四元数, Planner 进入半径后保留机器人当前朝向, 因此现有单点停止路径不能保证机器人面向目标

计划新增 `TARGET_OBSERVATION` 状态, 将“到达粗目标观察位置”和“最终找到目标”明确分开

预期流程:

```text
TARGET_APPROACH_COARSE
  -> 到达目标附近的安全观察距离
  -> TARGET_OBSERVATION
  -> 先对准目标并短暂停留
  -> 获得 STABLE_VISION 或 LIDAR_LOCKED
  -> TARGET_APPROACH_METRIC
  -> 最终到达并确认 REACHED
```

默认动作不是原地旋转, 而是对准粗目标并保持目标处于最合适相机的视野中央

推荐顺序:

1. 根据机器人和粗目标位置计算目标方位, 不使用融合消息中的单位 orientation
2. 在距离粗目标约 2.5 至 3.0 m 的安全观察距离停止, 不直接把粗目标点当作需要踩到的位置
3. 原地调整 yaw 对准目标, 然后静止观察 1.5 至 3.0 s
4. 静止期间优先获得连续 2D Mask 和连续 LiDAR 前景簇, 成功后立即进入稳定目标接近
5. 如果目标离开画面, 只围绕预测方位执行小角度重捕获, 不做 360 度旋转
6. 如果目标仍可见但三维估计不稳定, 再沿安全弧线或横向移动形成新视差

“对准后等待”适合解决视觉得分在 0.114 至 0.129 附近波动、Mask 窗口频繁失效和 LiDAR 连续帧不足的问题, 应作为第一选择

如果短暂停留后仍没有稳定目标, 应选择附近新的安全观察点, 而不是永久保持单点停止路径

需要注意, 粒子滤波器当前要求新视角具有至少 0.3 m 横向基线和至少 3 度夹角, 单纯原地旋转不一定能产生新的有效三角化视角

Unity 前相机相对 base 中心约有 0.3 m 偏移, 大角度转身在理论上可能形成一定相机位移, 但目标容易离开同一相机视野, 也不能稳定替代真实横向基线

因此粗目标观察分三级:

1. 面向目标静止观察, 用于获得连续 Mask 和更多 LiDAR 投影
2. 目标丢失时围绕预测方位小角度扫描, 只负责重新捕获
3. 目标可见但融合不稳定时沿安全弧线或横向移动 0.5 至 1.0 m, 移动时持续朝向目标, 主动形成新的观察基线

完整原地旋转既会主动丢失目标, 又不能保证有效平移视差, 禁止作为目标定位默认动作

### 6.3 粗目标接管前的证据保护

首次 Mask 到粗目标接管的 26.2 s 延迟发生在 `PENDING` 和低置信度 `TRACKING` 阶段, 只修改到达粗目标后的动作不能解决这段延迟

在首次确认 Mask 或融合进入 `PENDING` 后, 应短时间保护当前目标证据:

- 暂停快速切换探索分支, 避免机器人立即转身让目标离开相机
- 允许沿当前安全路径低速继续移动, 利用自然位移产生多视角基线
- 目标接近画面边缘时, 优先小角度调整朝向, 不立即停止或大角度旋转
- 保护时间先设为 2 至 3 s, 超时仍没有第二视角时恢复普通探索
- `PENDING` 不能直接接管导航 goal, 仍需保持现有置信度和物理门控

该阶段的目标是“保持看得见并继续获得视差”, 不是“原地等相同画面重复确认”

### 6.6 验收目标

- 清晰可见目标从首次进入候选到粗目标接管, 平均不高于 5 s, P95 不高于 10 s
- Goal Mux 接受目标到 Planner 发布路径不高于 0.5 s
- 到达粗目标后 0.5 s 内进入观察状态, 不出现无解释的长期单点 hold
- 进入观察状态后机器人朝向目标, 目标位于至少一个相机的有效视野内
- 目标持续可见时不执行完整原地旋转
- 观察阶段最终进入 `STABLE_VISION` 或 `LIDAR_LOCKED`, 或明确超时并切换新观察点
- 无目标场景连续运行至少 10 分钟不产生错误目标导航
- LiDAR 精修率明显高于当前 7.7%, 如果目标物理回波不足则必须由失败分类日志明确证明
- 最终状态进入 `REACHED`, 不能只停留在 `TRACKING`
