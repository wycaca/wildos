#### 当前边更新逻辑的结构性缺陷

1. 栅格变化和实际执行粒度不一致

   `_node_ids_near_newly_free()` 使用约 `0.5 × edge_radius + clearance + cell_diagonal`, 当前约为 4.78 m 的影响半径查找旧节点

   少量分散的新增 free cell 就可能覆盖 30 m 局部窗口中的大部分节点, 每个命中节点随后又查询最多 24 个近邻候选

   实际传播链为:

   `changed cell -> 半径内节点 -> 每个节点的近邻候选 -> 节点全部关联历史边`

   这不是边级增量更新, 只是通过空间索引缩小过的节点级批量重建

2. unknown 重试丢失了精确索引带来的收益

   `_blocked_unknown_retry_nodes()` 已经能够找到真正经过新增 free 附近的候选 pair, 但随后把 pair 转成两个端点 ID

   `build_edges()` 不会只重试命中的 pair, 而是重新生成两个端点各自的近邻候选

   精确传播链被放大为:

   `changed cell -> exact blocked pair -> 两个端点 -> 两端点全部近邻候选`

   1149 条命中候选还会共享大量端点, 当前统计只记录去重后的节点集合, 没有记录每种触发原因各自造成的候选检查量

3. 候选选择和历史边保留存在语义冲突

   `build_edges()` 对普通节点只选择最近 4 条有效边, 但 `merge_historical_edges()` 会把未被当前障碍证伪的受影响历史边重新加入

   因此 `max_edge_neighbors=4` 只限制本次新选择, 不是持久图的不变量

   当近邻排名变化时, 旧的安全边不会因为已经不在前 4 名而退出, 新边又可以继续加入

   这有三个后果:

   - 节点实际度数和边数量可能随历史选择累积
   - 重建节点时需要复查越来越多的关联历史边
   - 普通近邻边、已走通历史边和关键桥接边没有明确的角色和不同生命周期

   当前 478 nodes、1754 edges 的平均度数约为 7.34, 仅凭这个数值还不能证明边已经无界增长, 但现有代码确实没有维护明确的持久度数或边角色不变量

4. unknown 阻挡候选缺少淘汰策略

   `_sync_unknown_blocked_candidates()` 会保存本次检查中被 unknown 阻挡的 pair

   候选只有再次被检查或端点删除时才会移除, 没有以下生命周期约束:

   - 端点已经离开当前 rolling window
   - pair 已经不在任一端点的候选预算内
   - 已有更短或更稳定的替代边
   - 长期没有对应区域的观测变化
   - 候选只属于已断开的旧近邻排名

   因此候选数量可以随探索历史增长, 最近已经达到约 6700 条, 每次地图开放都可能唤醒大量过期或低价值候选

5. 局部替换仍产生大量重复工作

   当前流程先收集重建节点的全部关联边, 再执行:

   - 对所有重建节点重新查询和排序近邻
   - 对所有候选重新做走廊和净空检查
   - 对所有受影响历史边再次做局部冲突检查
   - 从邻接索引和边空间索引删除旧边
   - 创建新 `InternalEdge` 并重新插入索引

   即使只有一条候选走廊状态变化, 同一节点其他无关边也会经历检查和索引更新

6. 现有基准覆盖的是有利路径, 没有复现长期运行负载

   当前固定图基准验证了稳定地图、少量新障碍和 free 变 unknown

   其中稳定地图和 free 变 unknown 本来就可以直接跳过大部分旧边工作, 没有覆盖最近日志中的主要负载:

   - 分散的 unknown 变 free
   - rolling map 持续移动
   - 新节点和新 free 同时出现
   - unknown 阻挡候选长期累积后集中开放
   - 低连接重试与普通重建叠加
   - 近邻排名变化后的旧边淘汰

   因此 1.1 至 7.3 ms 的微基准结果不能代表 10 分钟运行后的边更新性能

7. 当前性能日志不能建立单帧因果关系

   阶段耗时使用一段时间内的平均值, `最近工作量` 只保存最后一帧

   例如最后一条日志显示最后一帧没有重建节点和候选, 但边阶段窗口平均仍为 148 ms

   这不代表空操作本身耗时 148 ms, 而是统计窗口中仍包含之前的重负载帧

   在改成逐帧耗时与逐帧工作量配对前, 只能判断总体相关性, 不能可靠定位单个子步骤占比

### 设计判断: 边更新子系统需要重新设计

不需要推翻地图分类、节点生成、Frontier 或持久图存储, 但边候选、边状态、失效传播和增量写入需要从“重建节点的边”改为“更新受影响的精确 pair”

继续调整影响半径、近邻数量或重试次数只能暂时降低工作量, 同时会再次引入漏连边风险, 无法同时解决性能、节点覆盖洞和桥接边缺失

目标模型:

| 当前模型 | 目标模型 |
|---|---|
| cell 变化先转换为节点集合 | cell 或 tile 变化直接命中 edge pair |
| 重建节点的全部近邻和关联边 | 只验证状态真正可能变化的 pair |
| 新边、历史边、桥接边共用一个集合 | 区分 local、historical 和 bridge 角色 |
| unknown 候选只增不主动淘汰 | per-node、per-tile 预算和过期策略 |
| 删除后重建局部边对象和索引 | 对精确 edge key 做 add、remove、keep |
| 近邻选择与安全验证同时执行 | 候选发现、走廊验证和拓扑选择分层 |

### 边更新重设计方案

#### 阶段 0: 先补齐诊断和不变量

- [ ] 每帧配对记录阶段耗时和工作量, 不再混用窗口平均与最后一帧
- [ ] 分别记录 `new_node`、`new_free_radius`、`unknown_retry`、`current_node`、`low_degree` 对重建集合的独立贡献和去重后贡献
- [ ] 记录边空间索引粗命中数、精确命中数、候选发现数、走廊验证数和索引增删数
- [ ] 记录 active local、historical、bridge、blocked unknown 和待处理队列的数量
- [ ] 增加每个节点按边角色统计的度数, 检查普通近邻预算是否实际生效
- [ ] 增加 blocked candidate 的新增、重试、过期、超预算和端点离窗统计
- [ ] 修正 `details/graph_update.md` 中“边更新时间已主要取决于真实变化”的结论, 标记为尚未达成

#### 阶段 1: 在现有架构内先限制放大

- [ ] unknown 开放后直接重试空间索引命中的 exact pair, 不再转换为两个端点的整邻域重建
- [ ] 新障碍直接失效真正经过变化区域的 active edge key, 安全删除保持最高优先级
- [ ] 只有新节点和覆盖修复节点执行候选发现, 普通新 free 不再默认扫描 4.78 m 内全部旧节点
- [ ] 新 free 只唤醒经过对应 cell 或 tile 的 blocked pair, 没有历史 pair 时再进入有预算的局部缺边发现
- [ ] 为 blocked unknown 候选增加 rolling window、近邻排名、时间和 per-node 数量淘汰
- [ ] 将低连接重试改成独立有界队列, 不与同帧全部变化重复扩散
- [ ] 对低优先级候选验证设置每帧预算并允许延期, 新障碍安全删除不能延期

阶段 1 只用于验证失效粒度和快速控制高峰, 不能以减少检查为理由跳过节点覆盖修复或跨分量桥接检查

#### 阶段 2: 拆分并重写边状态管理

- [ ] 建立统一的无向 pair 状态, 至少区分 `ACTIVE_LOCAL`、`ACTIVE_HISTORICAL`、`ACTIVE_BRIDGE`、`BLOCKED_UNKNOWN`、`BLOCKED_OBSTACLE` 和 `RETIRED`
- [ ] 每个 pair 保存端点、边角色、最后验证的地图版本、空间包围盒或 tile 占用以及最后活跃时间
- [ ] 建立 `cell/tile -> active pair` 和 `cell/tile -> blocked pair` 的反向索引, 地图变化只产生精确 dirty pair
- [ ] 将候选发现从走廊安全验证中拆出, 只在新节点、节点移动、覆盖洞修复和连通分量变化时发现新 pair
- [ ] 将拓扑选择从走廊验证中拆出, 普通节点维护有滞回的固定近邻预算, 桥接边使用独立预算
- [ ] 历史已确认边在局部变 unknown 时保持有效, 但必须有明确角色和淘汰规则, 不能依赖每次 `merge_historical_edges()` 回灌
- [ ] 更新结果使用 edge delta, 只对精确 key 执行 add、remove 或 role change, 不再删除并重插节点的全部关联边
- [ ] 新障碍、节点删除和端点失效使用同步高优先级事务, 候选补连使用可延期低优先级队列
- [ ] 图连通修复使用单独的 bridge 候选生成器, 不再依赖普通最近 4 邻边偶然保持连通

建议的代码职责拆分:

- `edge_candidate_index.py`: pair 空间依赖和 blocked candidate 生命周期
- `edge_validator.py`: 单个 pair 的 obstacle、unknown 和 clearance 验证
- `edge_selector.py`: local KNN、滞回和 bridge 角色选择
- `edge_updater.py`: dirty pair 队列、优先级和 edge delta 提交
- `edge_builder.py`: 仅保留初始化或离线全量构图能力

具体文件名可以在实现时调整, 但候选发现、状态验证、拓扑选择和图写入不能继续集中在同一个节点重建流程中

#### 重设计验收条件

- 地图变化只重新验证空间上真正相交的 active 或 blocked pair
- 1 至 10 个分散新增 free 不再默认重建大部分局部节点
- blocked unknown 候选受明确的 per-node、per-tile 和 rolling window 预算限制, 长任务中不单调增长
- 普通近邻边、历史边和桥接边分别满足各自度数与生命周期不变量
- 未变化边不重复做净空检查, 不删除对象, 不更新空间索引

- 保持现有新边不能穿过 unknown 或 obstacle、历史确认边不因局部 unknown 误删的安全语义
- 达到本节已有的 150 ms 平均边更新、500 ms 总耗时 P95 和 800 ms graph 消息年龄 P95 目标

### 新问题: 节点覆盖洞和关键边缺失

2026-07-23 Unity 截图中, 机器人附近存在一片视觉上连续的地面, 但局部没有普通图节点, 两侧已有节点也没有形成直达边

Planner 只能在已有图上运行 Dijkstra, 底层图缺少直达拓扑后只能选择上方绕行路径, 这不是 Planner 路线代价本身导致的绕路

截图中的黄色大点是当时仍在显示的 `current_node` Marker, 当前版本已经取消该 Marker

截图中的蓝色网格使用 elevation layer 着色, 只能证明该位置有高程表面, 不能证明 Graph Construction 最终把对应 cell 分类为可采样 `free`

节点生成还需要依次满足:

1. traversability 达到 free 门槛且 elevation 有效
2. 属于机器人可达或允许采样的 free 连通分量
3. 固定世界网格采样位置落在 free cell
4. 采样点距离 obstacle 至少 0.5 m
5. 附近 1.0 m 内没有已有节点
6. 通过按 free radius 选择的自适应网格层级

当前配置的基础采样间距约为 `6 × 0.2 m = 1.2 m`, 开阔区域会使用约 2.4 m 的稀疏层级

当前实现只检查固定网格交点, 如果交点恰好落在 unknown、低 traversability 或净空不足位置, 不会在附近空地寻找替代点

连续多个网格交点被拒绝后, 即使周围视觉上是空地, 也可能形成明显大于名义采样间距的节点覆盖洞

已有节点没有连边还有四个独立限制:

- 两节点距离必须不超过 8.0 m
- 候选先截断为距离最近的 24 个节点
- 普通节点最终只选择最近的 4 条无碰撞边
- 整条边及其 0.5 m 净空必须避开 obstacle 和 unknown

纯最近邻策略不能保证图连通

节点在各自局部已经有 2 至 4 条短边时, 即使两个局部图分量之间存在安全直线, 跨分量桥接边也可能在候选截断或 4 条边限制处被丢弃

低连接重试只检查节点度数, 不能发现“局部度数正常但全局仍断开”的情况

当前 RViz 只显示最终节点和边, 没有显示节点采样、候选边和净空检查的拒绝原因, 因此仅凭截图还不能区分该位置具体是 `not_free`、`unreachable`、`clearance`、`lattice`、`unknown` 还是邻居限额拒绝

截图时间约为 14:56:35, 邻近一帧性能日志记录:

- 当前窗口约 194 个节点, 历史图约 423 个节点
- 本帧重建约 194 个节点的边
- 生成并检查约 2702 条边候选
- 累计记录约 6418 条 `unknown` 阻挡候选
- 本帧因 unknown 开放重试约 1149 条候选

这些统计不能单独证明截图中的某条直线由 unknown 阻挡, 但能确认当时大量候选正在受 unknown 分类和局部重建影响, 与缺边现象一致

### 解决方案

第一阶段先补诊断, 不直接放宽安全条件:

- 增加局部节点采样诊断 Marker, 区分 `not_free`、`unreachable`、`obstacle_clearance`、`adaptive_lattice` 和 `node_separation`
- 增加候选边诊断 Marker, 区分 `outside_radius`、`candidate_limit`、`obstacle`、`unknown`、`clearance` 和 `neighbor_limit`
- 日志增加可达 free 覆盖率、最大无节点空洞半径、局部图分量数和跨分量可连接候选数
- 保存发生绕路时机器人附近的 classified grid、节点、候选边和拒绝原因, 允许离线复现截图场景

第二阶段修复节点覆盖, 但不全局提高采样密度:

- 固定网格采样完成后检查当前可达 free 到最近图节点的距离
- 只在超过覆盖上限的局部空洞中补充节点
- 补点位置选择空洞内净空最大的安全 free cell, 不要求正好落在固定网格交点
- 只处理新增 free、机器人附近和当前图路径附近的覆盖洞
- 每帧限制补点数量, 避免节点数和边处理量失控

第三阶段增加有界的图连通修复:

- 在同一个 reachable free 分量内计算局部图连通分量
- 对相邻但断开的图分量查询最近的跨分量节点对
- 跨分量候选仍必须通过 obstacle、unknown 和 0.5 m 净空检查
- 允许每个节点额外保留少量桥接边, 桥接边不被普通 4 条最近邻限额淘汰
- 候选搜索改为持续检查近邻, 直到找到足够的有效边或达到碰撞检查预算, 避免前 24 个候选都被障碍挡住后提前结束
- 只在新节点、新 free、低连接节点或局部图分量变化时触发, 禁止每帧全图两两检查

第四阶段增加回归测试:

- 构造固定网格交点落在障碍边缘、附近仍有安全空地的场景, 验证能够补点
- 构造两组局部度数均正常但彼此断开的节点, 验证生成安全桥接边
- 构造桥接边穿过 unknown 或 obstacle 的场景, 验证不会为了连通而放宽安全条件
- 对截图对应场景做离线回放, 验证最短路径不再从上方绕行
- 记录修复前后的节点数、候选边数、碰撞检查数、图更新时间和路径长度

验收条件:

- 机器人可达 free 区域内不再出现超过覆盖上限的无节点空洞
- 同一 reachable free 分量中的图节点在存在安全桥接线时保持连通
- 修复后截图位置能够生成直达图路径, 不再无理由从上方绕行
- 不在 unknown、obstacle 或净空不足区域生成节点和边
- 节点与桥接修复不能让边处理平均耗时超过现有性能目标

验收目标:

- 500 nodes、约 1700 edges 时平均总耗时不高于 350 ms
