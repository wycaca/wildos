# Graph Construction 当前概览

日期: 2026-06-22

修订: 2026-07-13

目标: 整理 `graph_construction` 在当前 WildOS 仓库中的项目目标, 系统位置, 输入输出接口和实现边界

## 当前结论

`graph_construction` 是 WildOS 的几何记忆层, 负责把局部几何地图转换成稳定的稀疏 `NavigationGraph`

当前代码已经实现该模块, 不再是待复现的缺失组件

它的核心职责:

- 消费 elevation GridMap 或 2D OccupancyGrid
- 分类 free, obstacle, unknown 和 frontier
- 维护稳定 node UUID, historical edges 和 current node
- 发布 `/spot1/nav_graph`
- 给 WildOS 视觉评分提供 geometric frontier
- 给 `graphnav_planner` 提供可搜索的 graph 拓扑

它不负责:

- 训练 ExploRFM
- 生成语义 `frontier_scores`
- 直接控制底盘
- 发布 `cmd_vel`
- 替代 `graphnav_planner`

## 当前系统位置

默认主线是 elevation/2.5D GridMap 后端:

```text
PointCloud2
  -> pointcloud_axis_adapter
  -> elevation_mapping_cupy
  -> /elevation_mapping_node/elevation_map_raw
  -> graph_construction
  -> /spot1/nav_graph
  -> visual_navigation WildOS scoring
  -> /spot1/scored_nav_graph
  -> object_search_goal_mux
  -> graphnav_planner
  -> path output
```

2D OccupancyGrid 只是 fallback:

```text
PointCloud2 or aligned PointCloud2
  -> livox_grid_builder
  -> /spot1/traversability_grid
  -> graph_construction
  -> /spot1/nav_graph
```

视觉链路只影响 frontier scoring 和 object search goal selection, 不直接修改几何地图

## 当前启动入口

当前 source tree 中的脚本入口是:

```bash
./scripts/start_wildos_elevation.sh
```

常用 profile:

```bash
./scripts/start_wildos_elevation.sh
WILDOS_TOPIC_PROFILE=unity ./scripts/start_wildos_elevation.sh do_object_search:=true
WILDOS_TOPIC_PROFILE=robot ./scripts/start_wildos_elevation.sh do_object_search:=true
```

2D fallback 保留 launch 文件, 但没有对应脚本:

```bash
ros2 launch graph_construction wildos_2d_sim.launch.py topic_profile:=unity
```

不要引用旧的 `scripts/start_wildos_2d.sh` 或 `scripts/start_wildos_3d.sh`, 当前 source tree 中不存在这两个脚本

## Topic 和 Frame 来源

平台差异集中在:

```text
graph_construction/configs/topic_profiles.yaml
```

内置 profile:

- `isaac`, Isaac Sim 5.1 Go2, raw LiDAR `/unitree_go2/lidar/points`, path `/path2`, goal `/goal_pose`
- `unity`, Unity 仿真, elevation 输入 `/livox/lidar`, 2D fallback 输入 `/mapokk`, path `/multi_planned_path`, goal `/spot1/graphnav_goal_pose`
- `robot`, 真实机器人占位 profile, 需要按现场 topic 和 TF 更新

Unity 的当前约束:

- elevation 主线使用 raw `/livox/lidar`
- 2D fallback 使用已经对齐到 `odom_3D` 的 `/mapokk`
- 2D fallback 必须保持 `lidar_assume_input_in_grid_frame=true`
- 不要把 raw `/livox/lidar` 直接替换成 2D fallback 输入
- Unity 高层 goal topic 使用 `/spot1/graphnav_goal_pose`, 避免触发外部 `nav_slam/astar` 的公共 `/goal_pose`

## NavigationGraph 接口

`graphnav_msgs/msg/NavigationGraph.msg`:

```text
std_msgs/Header header
string[] trav_classes
Node[] nodes
Edge[] edges
uint32 current_node_idx
```

`Node.msg`:

```text
UUID uuid
geometry_msgs/Pose pose
NodeTraversabilityProperties[] trav_properties
KeyValue[] properties
```

`NodeTraversabilityProperties.msg`:

```text
bool is_frontier
geometry_msgs/Point[] frontier_points
float32 explored_radius
float32 free_radius
KeyValue[] properties
```

`Edge.msg`:

```text
uint32 to_idx
uint32 from_idx
EdgeTraversability[] traversability
KeyValue[] properties
```

`EdgeTraversability.msg`:

```text
float32 traversability_cost
KeyValue[] properties
```

当前默认 `trav_class` 是 `default`, node 和 edge 的 traversability 数组必须与 `trav_classes` 顺序一致

## graph_construction 输出要求

当前实现需要稳定输出:

- `header.frame_id`, graph 坐标系
- `nodes`, 稀疏空间节点
- `uuid`, 跨帧稳定的节点标识
- `edges`, collision-free graph 连接
- `current_node_idx`, 机器人当前节点或 anchor node
- `is_frontier`, 当前 node 是否拥有 frontier points
- `frontier_points`, free / unknown 边界点
- `explored_radius`, node 周围已探索半径
- `free_radius`, node 周围可通行半径
- `traversability_cost`, graph planner 使用的边权重

WildOS 视觉模块会在 node properties 中追加:

```text
key = frontier_scores
value = num_angular_bins 个方向评分

key = is_default_scored
value = [0.0] 或 [1.0]
```

因此 `graph_construction` 不生成语义分数, 但必须提供稳定且可投影的 frontier 几何信息

## 当前代码结构

```text
node.py
  ROS 参数, topic, QoS, timer, TF, 发布和诊断

grid_adapter.py
  OccupancyGrid / GridMap 解码为 ClassifiedGrid

grid_types.py
  ClassifiedGrid, 坐标转换, elevation 查询, collision line, distance field

graph_builder.py
  SparseGraphBuilder, 纯算法入口

graph_memory.py
  GraphState, InternalNode, InternalEdge, UUID 和历史记忆

frontier_detector.py
  free / unknown 边界检测和 frontier owner 分配

edge_builder.py
  当前边生成, historical edge validation, robot anchor 连边

msg_utils.py
  GraphState 转 graphnav_msgs/NavigationGraph

viz.py
  GraphState 和 ClassifiedGrid 转 MarkerArray

livox_grid_builder.py
  2D fallback 点云转 OccupancyGrid

pointcloud_axis_adapter.py
  elevation 主线点云轴向和 frame 适配

grid_map_to_occupancy.py
  GridMap debug projection, 不在主链路中使用
```

## 当前实现边界

关键边界:

- 纯算法层不导入 `rclpy` 或 ROS message package
- ROS message 解码集中在 `grid_adapter.py`
- ROS message 生成集中在 `msg_utils.py`
- topic, frame, 参数和发布集中在 `node.py`
- GridMap rolling buffer 和坐标映射必须用测试或运行数据确认

当前 graph 行为:

- elevation path 直接消费 `/elevation_mapping_node/elevation_map_raw`
- 小型 elevation NaN 洞会在 graph adapter 内为 free cell 补 elevation
- 历史 edge 默认保留, 只用当前可见障碍证伪
- `prune_disconnected_nodes` 默认关闭
- 脚下点云缺失时启用 robot anchor current node
- graph edge 要求 line 和 clearance 都安全

## 与 WildOS 论文的关系

WildOS 论文中 sparse navigation graph 的价值是:

- Spatial memory, 在长距离探索中保留已走过区域和未完成 frontier
- Safe geometric grounding, 视觉模型只影响语义偏好, 可执行路径仍受几何 graph 约束

当前实现保留这个分工:

- `graph_construction` 输出几何 graph
- `visual_navigation/wildos/nav.py` 为 frontier 加视觉分数
- `object_search_goal_mux` 在目标, 目标记忆和几何探索之间切换
- `graphnav_planner` 在 scored graph 上求路径
